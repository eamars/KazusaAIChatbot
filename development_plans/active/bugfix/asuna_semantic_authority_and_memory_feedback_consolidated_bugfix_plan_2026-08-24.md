## Problem And Evidence

The current failure mode is semantic authority capture, expressed through one
self-reinforcing loop:

```text
learned character tendency
  -> character uses a visible tactic
  -> Conversation Progress overstates the tactic as a decision constraint
  -> cognition reselects it despite a changed current user request
  -> L3/dialog faithfully repeat the payoff
  -> consolidation can misstore the character demand as a user agreement
  -> reflection can promote repeated behavior as global character authority
  -> later users and later turns receive stronger pressure
```

Two current evidence sets establish the system boundary:

1. Latest-anchored QQ group `480386272` evidence shows distinct participant
   IDs and correct triggering-user binding. The defect occurs later, when a
   relationship, consent, promise, permission, or intimate role addressed to
   one participant is treated as applicable to another participant.
2. The fresh memory-enabled L2 replay shows Asuna answering a changed task and
   then returning to her unanswered reward proposal. Conversation Progress
   marked that proposal `decision_critical`; consolidation then wrote the false
   `active_commitment`:

```text
用户同意在获得一之濑明日奈的决策协助后，提供一份具体的奖励作为交换。
```

The user made no such agreement.

## Confirmed Decisions

1. Memory-driven character evolution is intentional. Memory may shape
   motivation, stance, voice, and tactics.
2. Memory evidence is not current user intent, consent, permission,
   commitment, relationship ownership, or a mandatory visible response goal.
3. QQ/platform identity binding is mechanically correct in the captured
   incident. Recipient applicability after identity binding is defective.
4. Current accepted user evidence owns the current semantic delta. Historical
   continuity and character tendency remain supporting or conditional inputs.
5. A character-authored proposal may remain factual scene continuity. Until
   the current user responds to it, it is not the user's goal, blocker,
   acceptance, obligation, or decision constraint.
6. Continuing the underlying practical task does not accept or reopen a prior
   character-authored offer, demand, bargain, condition, or relational payoff.
7. `active_commitment` is character-owned future behavior accepted for the
   current user. It does not represent a debt or promise imposed by the
   character on the user.
8. Public group visibility proves what was said, by whom, and to whom. It does
   not transfer one participant's permission or relationship to another.
9. Repeated character behavior may qualify as global lore or conditional
   self-guidance only after target-removal, privacy, identity, and scope review.
10. Whole-database erasure is rejected as the repair. The data path is a
    read-only audit followed by a separately approved exact lifecycle manifest.
11. The live response path remains one A1, one A2, one G, one P, one content
    plan, and one dialog call. No semantic evaluator, retry loop, response
    suppressor, or foreground database read is added.
12. The current multi-emotion derivation, state, projection, order, causes,
    limits, reducers, and persistence contracts remain unchanged.
13. The existing resolver-readiness evaluation and the broader unsupported
    autobiography/temporary-role work remain under their independent active
    plans and ownership.

## Target State

### 1. Live semantic authority

The live path keeps its existing stages:

```text
current observation
  -> A1 observation/appraisal question
  -> A2 character judgment with bounded evidence
  -> G one current response goal
  -> P one coherent response plan
  -> L3 one bounded content plan
  -> dialog final wording
```

Authority is interpreted as follows:

- current user input and explicit current-user corrections own the current
  semantic delta;
- direct facts establish only facts within their declared scope;
- participant continuity establishes prior actors, actions, outcomes, and
  current scene history;
- conditional character guidance shapes tactics, motivation, and boundaries;
- personality, relationship, and affect shape judgment and voice after the
  current objective is fixed;
- none of the supporting lanes independently establishes current user intent,
  consent, permission, commitment, or required payoff.

`overused_moves` remains an LLM-authored observation of visible response
maneuvers that already occurred. Deterministic code copies at most four rows,
in order, at most 120 characters each. A1 does not receive the list. A2, G, P,
and L3 receive the exact same bounded list. The list is neither a prohibition
nor a future-response instruction.

G selects a primary contribution to the latest observation. A prior tactic may
be selected again when the user explicitly accepts, rejects, responds to,
references, asks about, materially changes, or reopens it. P, L3, and dialog
preserve that selected meaning and may not add an unselected relational or
contractual payoff.

### 2. Conversation Progress ownership

The existing scene and event calls, output shapes, relevance enum, persistence
schema, route, caps, and source references remain unchanged.

The scene observer follows these fixed semantics:

- `user_goal` and `current_blocker` require user-owned evidence;
- a character-authored unanswered offer, demand, bargain, condition, or
  relational payoff may appear in factual narrative/current-thread context;
- that proposal does not become user acceptance, obligation, goal, or blocker;
- an explicit current-user response may make it part of user-owned current
  state.

The event observer follows these fixed semantics:

- preserve the exact actor, action, object, beneficiary, precondition, and
  lifecycle evidence;
- an unanswered character-authored proposal has `scene` or `history`
  relevance;
- it has `decision` relevance only when the current user responds to, accepts,
  rejects, references, asks about, materially changes, or explicitly reopens
  it;
- continuing the underlying task alone is not such a response.

### 3. User-memory and active-commitment admission

The existing lane-router LLM remains the coarse semantic owner. The existing
single extractor call receives one code-owned dynamic contract:

```json
{
  "memory_unit_write_contract": {
    "enabled_lanes": ["user_memory_units"],
    "allowed_unit_types": [
      "stable_pattern",
      "recent_shift",
      "objective_fact",
      "milestone"
    ]
  }
}
```

The exact mapping is:

| Accepted lane | Allowed candidate types |
|---|---|
| `user_memory_units` | `stable_pattern`, `recent_shift`, `objective_fact`, `milestone` |
| `active_commitment` | `active_commitment` |
| both | the ordered union of both rows |
| neither | no extractor persistence work |

The extractor prompt defines `active_commitment` as future behavior accepted
by the character for the current user. It explicitly treats character demands,
user silence, and underlying-task continuation as insufficient. It returns an
empty list when no allowed durable meaning exists.

The deterministic validator receives the same allowed set. A candidate type
outside the set is a structural contract error: the candidate is logged and
dropped without semantic rewriting. Valid independent candidates remain
eligible. The one-attempt extractor budget and model-call count remain
unchanged.

### 4. Learned character-memory scope certification

The coarse consolidation router keeps its current output shape and receives
one target-removal decision rule: remove the source user, addressee,
relationship target, and private scene; if the accepted behavior is no longer
accurate and appropriate for the character with people generally, it is not
global character self-guidance.

The existing self-guidance specialist and reviewer independently emit:

```json
{
  "global_applicability": "global | scoped | absent",
  "target_specific_meaning_removed": true,
  "affects_identity_or_boundaries": false,
  "private_detail_risk": "low | medium | high",
  "user_details_removed": true,
  "reason": "bounded semantic justification"
}
```

Persistence admits a learned global self-guidance write only when both stages
agree on `global`, both confirm target removal, both exclude identity/boundary
ownership, and the final review reports low private-detail risk with user
details removed. Disagreement and structural failure produce no write. Code
does not choose another semantic lane.

`MemoryPrivacyReview` gains the exact three scope fields
`global_applicability`, `target_specific_meaning_removed`, and
`affects_identity_or_boundaries` for new learned-character writes. Seed and
curated knowledge retain their existing contracts.

Daily reflection promotion uses the same certificate. One independent
reviewer receives the promoter's one or two proposed writes in one candidate-
gated background call. It accepts or rejects exact candidates and cannot
rewrite them. Missing privacy evidence remains unreviewed. Identity/boundary
candidates remain owned by the existing identity-growth pipeline. This adds at
most one background call on promotion runs that propose a write and adds no
live-chat latency.

### 5. Typed retrieval and recipient applicability

Normal shared-memory projection and first-cycle prewarm preserve and partition
these fields before formatting:

- `memory_type`;
- `scope_type` and `scope_global_user_id`;
- `source_kind` and `source_system`;
- `authority`, `truth_status`, and `origin`;
- scope/privacy review fields;
- repository-owned source references for trace only.

The deterministic cognition connector maps typed metadata:

| Stored evidence | Cognition lane |
|---|---|
| exact current-user continuity | `participant_continuity` |
| `defense_rule` / character self-guidance | `conditional_character_guidance` |
| validated global `fact` or curated lore | `character_world_context` |
| mixed, unsupported, or incomplete learned metadata | excluded with diagnostic evidence |

A2, G, and P receive one compact rule: a public scene proves what was said, by
whom, and to whom; consent, permission, promise, relationship, or role
addressed to one participant does not transfer to another participant merely
because both can see it. A1 remains current-observation focused.

### 6. Targeted data audit and remediation

The read-only audit uses existing public `db.script_operations` exports and
the memory-evolution lifecycle API. It exports active learned global `fact` and
`defense_rule` rows from conversation-accepted and reflection-promoted sources
with exact IDs, hashes, authority, provenance, refs, and privacy metadata.

An offline LLM audit applies the same scope certificate and emits raw JSON.
The readable review separates:

- valid target-free global fact;
- valid target-free conditional self-guidance;
- scoped/private/relationship material;
- identity-or-boundary material;
- unresolved rows requiring user judgment.

The active `reflection_e0c29b7a8e2be3bff65b64640a719495` row named
`交换条件互动模式` is an explicit audit seed with no predetermined disposition.

The apply manifest contains exact memory-unit IDs, expected content hashes,
current statuses, reasons, and `reject` dispositions. After the user approves
that exact manifest, the repair tool backs up and re-fetches each row, stops on
drift, calls `memory_evolution.reject_memory_unit(...)`, verifies cache
invalidation, and re-audits. Valid rows remain unchanged. Historical rows are
not rewritten or automatically re-homed.

## Required Real-LLM And Service Gates

Each case runs separately, emits a durable artifact containing input, model
configuration, rendered prompt or version, raw output, parsed output, relevant
state, and judgment notes, and receives parent inspection before the next case.

### R1 — recorder unanswered-proposal negative control

Use a character-authored bargain and a user turn that continues the underlying
task without responding to it. The real scene/event recorders must keep the
proposal outside user goal/blocker and outside `decision` relevance.

### R2 — recorder explicit-response positive control

The user explicitly accepts, rejects, negotiates, or asks about the proposal.
The recorder may treat it as current decision evidence while preserving exact
actor, precondition, and lifecycle ownership.

### M1 — captured false-commitment negative control

Run the real extractor on the captured task/reward context with only
`user_memory_units` enabled. It must emit no active commitment and no claim that
the user accepted or owes a reward. A legitimate workload memory or an empty
list is acceptable.

### M2 — accepted character-commitment positive control

Use a user-scoped request and visible character acceptance with only
`active_commitment` enabled. The extractor must preserve one character-owned
commitment and its source/time contract.

### S1 — private memory-enabled semantic release

Run the four-turn L2 sequence twice under independent fresh identities. One
initial personality tactic may appear naturally; changed connected turns must
advance their current questions without making that tactic the consecutive
dominant payoff. Post-turn memory must contain no fabricated agreement.

### S2 — correction and deliberate-continuation controls

Run the explicit current-user correction gate twice and the deliberate
continuation positive control once. Correction cannot become proof of its
opposite. Explicit user reopening must still allow a grounded prior theme to
continue and deepen.

### L1 — L3/dialog non-reintroduction

Use an accepted G/P goal that excludes a prior relational payoff. Content plan
and dialog must preserve character voice without restoring that payoff or
adding an unselected user intention, relationship, or commitment.

### X1 — cross-user recipient applicability

Use a group-shaped debug scenario with two distinct stable users. Participant
A supplies a relationship, consent, or permission statement addressed to A.
Participant B later requests analogous access. Protected packets must preserve
both identities and addressees; Asuna must judge B from B's current evidence
and cannot cite A's agreement as B's permission. A separate positive control
allows genuinely target-free global self-guidance to affect tone or tactics.

### P1 — promotion target-removal controls

Run one target-specific relationship-derived candidate and one genuinely
target-free character-guidance candidate through the real promoter/reviewer
pair. The first receives no learned global write candidate; the second may pass
only with matching scope/privacy certificates.

### B1 — bounded path and multi-emotion preservation

Run real `run_cognition` with at least five simultaneous event-root emotions:
sadness, anger, gratitude, embarrassment, and nostalgia, each with a distinct
active cause, plus four maximum-size move descriptors. A1/A2/G/P continuation
and affect rows must remain exactly equal in identity, order, phase, intensity,
trend, cause status, and cause summary. The latest observation must still own
the selected response goal. The call roster, prompt caps, and no-retry contract
must remain exact.

### D1 — read-only audit and exact apply gate

Run the audit against current learned global memory and prove zero writes. The
parent reviews every disposition and presents the exact apply manifest. Apply
execution begins only after user approval of that manifest. The post-apply
audit must show approved-invalid rows inactive, valid global controls active,
and cache state refreshed.

  internal test-fixture decomposition, command order, and artifact filenames
  while preserving every contract, path boundary, call count, and exact test
  node.

  retry, evaluator, compatibility alias, fallback, database operation,
  relationship reducer change, adapter change, or deterministic natural-
  language classifier.

  from inspected evidence. A semantic-quality decision requiring the user's
  subjective judgment is presented to the user.

  erase it. The parent classifies the failure and either keeps remediation
  inside the fixed contract or requests a plan amendment.
- The database operator applies only a user-approved exact manifest. Scope
  discovery, row classification, and audit are not mutation authority.

1. Asuna remains recognizably characterful and memory-influenced while changed
   user turns own their current response contribution.
2. Unanswered character-authored proposals remain factual scene/history
   continuity and never become user goals, blockers, decision constraints, or
   commitments.

   continuation of a prior theme.
4. `user_memory_units` alone cannot persist an `active_commitment` candidate.
5. Legitimate character-owned, user-scoped accepted commitments remain
   available and source-grounded.
6. Distinct group users remain distinct in identity, addressee, participant
   continuity, relationship, consent, permission, promise, and role semantics.
7. Valid global facts remain direct fact evidence; valid self-guidance remains
   conditional; incomplete or mixed learned metadata fails closed.
8. Target-specific, private, relationship, identity, or boundary meaning cannot
   become global character memory through redaction alone.
9. The exchange-condition promoted row and every audited row receive an exact
   review disposition; database changes affect only later user-approved IDs.
10. A1/A2/G/P, L3, dialog, recorder, extractor, and reflection calls remain
    within the declared overhead budget.
11. The original five-emotion real-LLM gate preserves exact continuation and
    affect rows, cause order, and mixed emotional motivation.
12. Every changed production path has a collected and passing exact
    deterministic owner node plus required supplemental live evidence.
13. No deterministic prose classifier, semantic postfilter, evaluator, retry,
    compatibility layer, whole-database erase, or hidden fallback is present.
14. Independent review has no unresolved required finding.
15. The user accepts the final evidence and lifecycle closure.

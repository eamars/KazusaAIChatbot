# Test Impact And Traceability

This matrix is part of [the development plan](../cognition_live_observability_and_gadget_plan_2026-09-05.md). Paths are repository-relative. Each row identifies one exact production source or governed artifact, its changed contract, owner, exact deterministic pytest nodes, supplemental evidence and prevented regression.

`NEW` means the implementation must create that named node; it does not exist as claimed coverage today. On 2026-09-05 the user explicitly directed removal of all existing deterministic tests impacted by this plan before development, while preserving real LLM tests. The 15 former `EXISTING` references have been retired from this matrix. The completed removal covers 327 test definitions across 48 files; see the [removal record](deterministic-test-removal.md) and [exact inventory with preservation hashes](deterministic-test-removal.json).

All remaining rows specify future acceptance work for the draft development plan. Collect their exact node IDs during implementation. Write fresh checks against observable contracts after the early runtime probe; the deleted implementation-coupled assertions are historical evidence rather than a baseline to restore. This preparation step creates no replacement tests.

Modes: **D** = deterministic owner unit test; **H** = deterministic handoff test using controlled model/capability responses; **J** = deterministic JavaScript function/DOM owner test using the repository's browser harness; **B** = rendered HTTP/browser integration; **L** = individually inspected real-model evidence. J tests execute the actual gadget reducer/renderer against explicit fixtures; source-string assertions and screenshots do not replace those owner tests. Use the current Python/browser test dependencies; introduce no frontend build system.

## Execution Rules

1. Record the changed-path baseline. Match every changed production path to one row above.
2. Create the NEW nodes from the new observable contracts after the early probe, update synthetic harness fixtures within the implementation scope, and collect the exact IDs. Retired nodes in the removal inventory are excluded from this gate. A missing, renamed or deselected NEW node fails the gate until the matrix and tests agree.
3. Run mapped D/H/J nodes with the project virtual environment. Run B1–B5 against the actual changed console and Brain observation transport; controlled semantic invokers isolate lifecycle failures from model randomness.
4. Run L1 alone and inspect its trace. Use the character-test and llm-trace-debug skills for this real debug-channel work. Do not batch unrelated live cases or use deterministic fixtures to claim prompt quality.
5. Retain timing, screenshots, page/console health, failure-state observations and current served-checkout identity. Verify both preserved HTML hashes and relative links without relying on the temporary preview server.
6. Have the independent reviewer inspect direct owner tests, propagation tests, UI evidence, disclosure and absence of production playback. Record acceptance and remediation separately.

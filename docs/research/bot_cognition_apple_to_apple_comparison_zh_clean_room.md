## 2. 阅读范围与证据规则

本报告全部论述先用中文独立推理后写成，不是任何英文报告的中文副本。正文、表头、标题、分析与限制说明均为简体中文；项目名、仓库名、URL、commit、代码标识符与文件路径保持原文。

| 标签 | 含义 |

### 2.2 分数与置信度含义

分数（0–5，整数）：

| 分数 | 含义 |
| --- | --- |
| 0 | 没有有意义支持，或设计明显不利于该维度。 |
| 1 | 极少或偶然支持；重要情形未处理或未记录。 |
| 2 | 常见情形得到部分支持，存在实质缺口或归属不明。 |
| 3 | 在已记录范围内有扎实实用支持，存在已知局限。 |
| 4 | 能力强、覆盖广、有运维支撑，仅剩有限缺口。 |
| 5 | 在困难情形、连续性、失败处理与操作控制上都有突出表现。 |

置信度（与分数相互独立）：

| 置信度 | 含义 |
| --- | --- |
| H | 在固定快照的源码中直接验证。 |
| M | 机制部分验证或依赖配置，整体行为有文档支撑。 |
| L | 主要依赖文档、设计计划或需要实机确认的推断。 |

### 2.3 评分原则

- 先比结果、后比机制：先问机器人在该情境能否表现良好，再记录它如何做到。
- 证据与愿景分离：源码事实、官方文档声明与审阅推断使用不同标签。
- 只对证据支持的范围内打分：可选、实验性、计划中或依赖部署配置的功能不按全量能力计分。
- 奖励有用的简单性：阶段、字段、代理或痕迹多本身不加分；只有当它们改善结果且没有不可接受的延迟、成本或运维负担时才加分。
- 暴露权衡而非强推单一赢家：报告指出各设计在何处强、何处弱，以及什么使用场景让该权衡合理。

## 4. 十个中立维度的判读口径

| 维度 | 核心问题（本报告判读口径） |
| --- | --- |
| C1 社交相关性与回应时机 | 是否识别消息何时重要、何时该说、何时该等、何时该退出：提及与非提及处理、相关性/注意力处理、沉默与退出决策、线程契合、重复抑制、发言门控。 |
| C2 群聊与对话感知 | 是否随时间跟踪参与者、话题、轮次、指代、episode、打断与群噪：目标绑定、线程/话题状态、watermark、快照、补发、episode 状态、并发消息处理。 |
| C3 连续性与记忆质量 | 是否在合适时间与范围内记住有用信息，同时限制陈旧、冲突、无关与私密材料：短/长/episodic 记忆、检索排序、摘要、衰减、整合、纠错/删除、来源或证据标签、隐私范围、重启行为。 |
| C4 人格、个性化与情绪适应 | 是否保持可识别身份，并对不同人与情境适应语调、情绪、边界与关系行为：persona 处理、逐用户状态、关系或情绪信号、风格适应、角色学习、状态持久化、冲突控制。 |
| C5 能动性与互动管理 | 是否能选择回答/提问/等待/推迟/跟进/行动/沉默，并自然维持或结束对话：显式或隐式行动选择、意愿/优先级、开放循环跟踪、主动接触、调度器、用户控制边界。 |
| C6 回应质量与表达控制 | 最终消息是否匹配所选社交目的、目标、平台与角色声音：决策与措辞的分离或协调、目标/引用处理、格式、多模态表面、投递归属、改写行为、可见输出校验。 |
| C7 工具与能力实用性 | 工具、检索、插件、MCP、子代理与定时任务是否扩展有用行为而不使机器人不可预测：发现、参数校验、能力范围、权限、结果处理、专业组合、幂等、错误返回。 |
| C8 可靠性、延迟与降级 | 在模型错误、慢工具、高消息量、长上下文、重启与部分失败下是否仍可用：超时、循环/token 上限、队列/背压、重试、回退、压缩、陈旧工作失效、持久化/恢复、端到端延迟证据。 |
| C9 安全、隐私与用户控制 | 是否保护私密内容、限制不想要的联系与动作、允许操作者或用户检查/纠正/禁用/删除持久行为：数据边界、隐私过滤、授权、投递控制、可审计、可编辑记忆、保留/删除、配置门、提示/工具隔离。 |
| C10 可运维性、可扩展性与总成本 | 维护者能否长期部署、测试、观察、扩展并负担该系统：平台适配器、模型可移植性、插件架构、可测试性、诊断/重放、配置负担、资源要求、依赖复杂度、运维成本。 |

## 8. 逐项目画像

### 8.1 Kazusa

- 主要优势：显式认知轨迹把"观察到什么、谁的关系、证据支持什么、哪个目标胜出、提交了什么状态"变成可回放语义记录；RAG/解析器证据与立场、措辞、权限分离；确定性失败关闭与受保护痕迹；多轴关系与情绪由类型化原因推导；群聊场景、参与者绑定与沉默决策有明确契约。
- 主要不足：目标架构是草稿，不能当作全部已实现行为；每轮涉及多个 LLM 阶段，延迟与 token 成本高；外部工具/插件生态在本地资料中证据有限；配置与运维负担大。
- 适用场景：长期运营、需要角色一致性、证据边界、权限审计与可回放的社交机器人；对单轮延迟与成本不敏感、愿意投入运维的部署。
- 成本与权衡：用每轮多阶段 LLM 调用与复杂状态换取"判断可解释、状态可提交、失败可关闭"。若需求只是"能聊、能记一点、不串台即可"，这套结构属于过度投入。

### 8.2 MaiBot（MaiSaka）

- 主要优势：确定性发言门控与 Planner 语义判断结合，回应时机实用；Planner/回复器分离让分析不外泄、措辞单独打磨；记忆分层（中期、人物档案、A_Memorix 向量/图/检索、episode、后台写入）完整；工具、插件、浏览器、MCP 与聚焦工具扩展面广；监控与重放出色。
- 主要不足：核心长期记忆默认可选关闭，文档承诺大于默认行为；Planner 是自由文本，无类型化语义评估器；情绪/关系是文本与静态后缀而非持久状态机；summary 导入解析边界弱于 episode/档案路径。
- 适用场景：愿意调配置、需要丰富记忆与可观测性、追求"能记住人和事"的长期机器人；适合运维能力较强、能接受功能开关组合复杂度的团队。
- 成本与权衡：中等偏高的部署与配置成本换来实用记忆与运维体验。若预算紧张且群规模小，可以关闭大部分记忆，退化为普通工具机器人。

### 8.3 AstrBot

- 主要优势：有界工具循环（max_step、重复工具提示、结果 token 上限、空输出重试）；agent-as-tool 与插件扩展模式官方化；reasoning_content 与完成文本分离、默认不展示；上下文压缩阈值明确。
- 主要不足：稳定核心没有社交相关性、类型化立场/轨迹、记忆来源或安全授权契约证据；MindSim 仍是未合并 PR；会话/人格/检索管理器存在但不等于类型化契约。
- 适用场景：通用 agent 工具链、需要把多个专业 agent 组合进一个机器人、重视"循环不会失控"与低认知成本的部署；群聊人格一致性要求不高时最合适。
- 成本与权衡：轻量、通用、扩展容易，但把社交判断交给自由工具循环，长期角色一致性靠外部提示词维护。

### 8.4 PetGPT

- 主要优势：观察/意愿/回复三分离，潜行模式降低误发；五档意愿是简洁、用户可懂的"想不想说"控制；本地 Markdown 记忆透明可编辑；桌面应用部署简单、成本低；MCP/技能/子代理扩展路径清晰。
- 主要不足：长期记忆文件替换仍是设计；全文本注入缺来源、时效与冲突策略；commit-before-expression、独立动作授权未证明；多项社交平台支持是计划。
- 适用场景：个人桌面陪伴、单人或小群使用、预算与运维能力有限、重视"看得见、改得动"记忆的用户。
- 成本与权衡：用简单与透明换取低成本与易用，牺牲正式记忆生命周期与高保证权限边界。对个人场景，这个权衡通常合理；对需要可审计判断的生产社交机器人则不足。

### 8.5 ATRI-bot

- 主要优势：speak/update/silence 结构化决策便于测试；pgvector + PGroonga 混合召回、RRF 与分类时间衰减适合群聊噪声；用户档案与记忆抽取/整合/去重/过期提供连续性；异步、队列、模型回退与权限层级是扎实运维基础；工具/沙箱/子代理面广。
- 主要不足：JSON 决策是顶层结果而非完整因果轨迹；档案与记忆文本注入无统一证据-立场边界；LLM 档案更新与记忆合并的可变背景路径所有权、隐私与幂等需审计；模型回退不等于语义再生。
- 适用场景：QQ 群长期运营、需要较强记忆检索与工具面、能部署 PostgreSQL/pgvector/Docker 栈、接受中等偏高运维成本的场景。
- 成本与权衡：重型存储与结构化决策换来群聊记忆质量与扩展性；如果不需要多群长期记忆，这些存储与整合开销属于过度投入。

### 8.6 Hermes

- 主要优势：群级注意力（空闲 5 秒/注意 1 秒窗口、退出宽限、silent 计数、episode 阶段）是处理群噪的实用控制器；judge 结构化字段（continuity/thread/phase/loop/progression）可作为更丰富语义评估的输入；不可变快照与 watermark/epoch 是良好并发原语；STM/LTM/EPI/工作流/wiki 多层记忆与隐私分级、衰减、整合；通用 cron 调度与工具集门控。
- 主要不足：决策主要是"一个预回复 judge + 通用 agent"，无并行评估/目标竞标/意图选择记录；EpisodeState 是对话进程而非情绪/关系/立场提交；记录器在回复后才更新（不满足 commit-before-expression）；条件性第二次 LLM 改写可改变措辞；EpisodeState 重启持久性未证明；QQ 自主联系未被证明。
- 适用场景：QQ 群高噪环境、需要克制发言与 episode 连续性、愿意接受功能面大与接线复杂的部署；适合把"注意力窗口/episode 控制"当作可复用模式的项目。
- 成本与权衡：用较多组件与配置换取群聊克制与多层记忆；若群噪不严重，两级判断窗口的收益有限，简单门控即可。

## 9. 简单设计与复杂结构的适用边界

### 9.1 简单 prompt/tool/agent 设计更好的场景

- 个人或小群陪伴：延迟敏感、预算有限、运维人员少。PetGPT 的本地透明记忆与 AstrBot 的有界工具循环在这个区间更有吸引力。
- 需求边界清晰：只要"能聊、能调用几个工具、能记少量会话"，AstrBot/PetGPT 的单一循环与 SQLite/文件持久化足够，复杂状态机只会增加故障面。
- 快速原型与扩展性优先：插件/agent-as-tool 模式让能力增量简单，AstrBot 官方扩展路径成本最低。
- 单平台轻量部署：桌面应用或单机器人进程即可，不需要多用户关系状态与审计轨迹。

### 9.2 复杂结构值得付出成本的场景

- 长期多用户/多群运营：需要跨时间、跨用户的一致性，MaiBot、ATRI-bot、Hermes 的记忆/检索/注意力机制能把"记得住、不串台、不乱说"转化为可观察结果。
- 角色判断需要可解释与可回放：Kazusa ECT 的类型化轨迹、证据句柄、状态提交与失败关闭，在"为什么这样说、哪些证据改变过判断、什么状态被允许变化"必须可审计时才有不可替代的价值。
- 权限与安全要求高：能力不得自授权、对话不得重新决定立场、投递前必须校验目标与权限，只有确定性边界（Kazusa 的 resolver/action 授权、ATRI 的权限层级、Hermes 的工具集门控）能提供保证。
- 群噪严重、需要克制：Hermes 的注意力窗口、episode 状态与退出宽限，或 MaiBot 的确定性发言门控，能把"少说、说对、适时退出"变成工程能力。

### 9.3 结论

复杂度本身不产生分数。只有把它转换成可观察的社交结果——更好的回应时机、更强的连续记忆、更高的一致性与安全、可接受的延迟成本——复杂结构才值得。反之，简单设计在低延迟、低成本、易运维维度上应被视为同等甚至更优的选项。

## 10. 证据限制与审阅边界

- 仓库静态审阅不是实机行为基准：本报告没有启动任何项目服务，没有真实对话、压力、延迟或记忆质量的运行测量。分数是"基于所读证据的结构化阅读"，不是 benchmark。
